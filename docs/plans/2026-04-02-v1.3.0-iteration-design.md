## 2. 变更 1: 业务岗 8 维度重构

### 2.1 类型扩展

`DimensionTemplate` 新增 `indicators` 字段：

```typescript
export interface DimensionTemplate {
  name: string
  weight: number
  definition: string
  positive: string
  negative: string
  questions: string[]
  indicators: string[]  // 新增: 关键评估指标
}
```

### 2.2 Sales 模板新维度定义

| 维度 | 权重 | 关键评估指标 |
|------|------|-------------|
| 目标感 | 15% | 清晰的目标分解能力；为达成目标愿意付出的行为证据；面对困难时的坚持力和毅力 |
| 勤奋度 | 15% | 加班/自主学习等额外时间投入；主动出击频率（拜访量、电话量）；利用休息时间提升业务的行为 |
| 沟通能力 | 15% | 表达清晰度与逻辑性；跨部门/跨文化沟通效率；冲突调解与共识达成能力 |
| 抗压能力 | 10% | 高压环境下的情绪稳定性；连续遭拒后的恢复速度与行动力；持续高强度工作的耐力 |
| 学习能力 | 10% | 新产品/新市场知识的掌握速度；学习方法论与自驱学习行为；将新知识转化为业绩的能力 |
| 销售能力（业务、英语水平） | 20% | 英语口语沟通水平（日常/商务/谈判级别）；谈判能力与成交技巧；客户开发能力（新客户获取）；以往订单总额/业绩数据 |
| 价值观 | 10% | 诚信正直的行为表现；团队协作精神与利他行为；对公司文化和制度的认同度 |
| 管理潜力 | 5% | 领导力萌芽（是否主动带新人、组织活动）；团队影响力与号召力；规划组织能力的初步体现 |

### 2.3 行为锚点

每个维度保留 `definition`、`positive`、`negative`、`questions`，内容根据新维度全部重写。

### 2.4 其他岗位类别

管理岗、专业骨干岗、职能支持岗 — 本次不改，为 indicators 字段补充空数组 `[]` 以兼容类型。

## 3. 变更 2: AI 评分差异化增强

### 3.1 问题根因

当前 `buildEvaluationPrompt()` 只传维度名+权重，AI 缺乏具体打分依据，倾向给 60-80 "安全分"，导致通过/淘汰候选人分差仅 1-2 分。

### 3.2 方案: 强化 Prompt

在 `prompts.ts` 中做 3 项增强：

**A. 注入关键评估指标**

```
## 评分维度（满分 100）
- 目标感（权重 15%）
  关键指标：清晰的目标分解能力；为达成目标愿意付出的行为证据；面对困难时的坚持力
```

**B. 注入分档评分标准**

```
## 分档标准（必须严格执行）
- 90-100：该维度表现卓越，简历/面试中有多条明确的优秀行为证据
- 70-89：该维度表现良好，有 2-3 条正面行为证据支撑
- 50-69：该维度表现一般，证据不足或正反参半
- 30-49：该维度表现较差，多数指标不达标或缺乏证据
- 0-29：该维度严重不足，几乎无正面证据
```

**C. 差异化指令**

```
⚠️ 评分规则：
1. 简历中无法找到某维度的支撑证据，该维度得分不得超过 40
2. 每个维度必须基于 indicators 逐条评判，不可笼统给分
3. 优秀候选人与不合格候选人的总分差距应在 20 分以上
4. 禁止所有维度给出相近分数，必须体现维度间的差异
```

### 3.3 代码变更

- `buildBehaviorContext()` — 新增 indicators 输出
- `buildEvaluationPrompt()` — 注入分档标准 + 差异化指令
- `buildReportPrompt()` — 同步 indicators 上下文

## 4. 变更 3: 报告附件上传 + AI 二次综合评估

### 4.1 流程

```
初评（已有）                    二次综合评估（新增）
┌─────────────┐               ┌─────────────────────────┐
│ 上传简历     │               │ 报告页上传面试补充材料    │
│ AI 初评      │───初评报告───→ │ （面试记录/录音转文字等） │
│ type:initial │               │ AI 综合 简历+初评+附件    │
└─────────────┘               │ 重新打分 → 综合报告       │
                              │ type: comprehensive       │
                              └─────────────────────────┘
```

### 4.2 数据模型

**新增 `attachments` 表:**

```sql
CREATE TABLE attachments (
  id TEXT PRIMARY KEY,
  assessment_id TEXT NOT NULL REFERENCES assessments(id) ON DELETE CASCADE,
  filename TEXT NOT NULL,
  original_name TEXT NOT NULL,
  file_path TEXT NOT NULL,
  file_type TEXT NOT NULL,    -- 'pdf' | 'docx' | 'txt' | 'audio' | 'image'
  file_size INTEGER NOT NULL,
  text_content TEXT,          -- 提取的文本（文档类自动提取，音频/图片为空）
  created_at TEXT NOT NULL DEFAULT (datetime('now'))
);
```

**Assessment 表变更:**

```sql
-- Migration 003
ALTER TABLE assessments ADD COLUMN type TEXT NOT NULL DEFAULT 'initial';
ALTER TABLE assessments ADD COLUMN parent_id TEXT REFERENCES assessments(id);
```

### 4.3 附件内容提取

| 文件类型 | 提取方式 |
|----------|---------|
| PDF / DOCX / TXT | 复用已有 `resume-parser` 提取文本 |
| 音频 (mp3/wav/m4a) | 存储文件引用，text_content 留空，UI 提示"请粘贴转写文字" |
| 图片 (jpg/png) | 存储文件引用，text_content 留空 |

### 4.4 AI 二次综合评估

新增 `buildReEvaluationPrompt()`：

```
输入:
  - 原始简历内容 (candidate.resumeText)
  - 初评结果 (assessment scores + strengths + weaknesses)
  - 附件文本内容 (面试记录等)
  - 8 维度 + 关键指标 + 分档标准

指令:
  "你现在拥有该候选人的简历和面试补充材料。请综合所有信息重新评分。
   如面试中发现简历内容不实或表现与简历不符，必须大幅调整分数。
   面试表现证据的权重应高于简历自述。"
```

**自动触发**: 附件上传完成 → 自动提取文本 → 自动调用二次评估 → 生成 `type: 'comprehensive'` 的 Assessment

### 4.5 UI 变更

报告页 (`/reports`) 增加：
- 附件上传区域（支持拖拽 + 点击，多文件）
- 上传后显示附件列表（文件名、类型、大小、删除按钮）
- 二次评估状态指示（分析中... → 完成）
- 综合报告展示（替代或并列初评报告）

## 5. 变更 4: 支持 3-5 人同时对比

### 5.1 当前限制

`CandidateCompare.svelte` 技术上已支持 N 人对比（基于 `assessments` 数组），但前端入口限制了候选人选择数量。

### 5.2 方案

- `/candidates` 页面：简历上传支持多文件（`multiple` 属性）+ 批量拖拽
- 评估结果页：增加多选复选框，可勾选 3-5 个候选人
- 对比视图：表格横向扩展，超过 3 人时横向滚动
- `ResumeUploader.svelte`：支持 `multiple` 模式，循环调用上传 API

### 5.3 代码变更

| 文件 | 变更 |
|------|------|
| `ResumeUploader.svelte` | 增加 `multiple` prop，支持多文件上传 |
| `assessment/results/+page.svelte` | 增加多选候选人 + "对比" 按钮 |
| `CandidateCompare.svelte` | 优化横向滚动，适配 5 人对比 |

## 7. 技术风险

| 风险 | 缓解措施 |
|------|---------|
| AI 二次评估耗时长 | 异步处理 + loading 状态指示 |
| 附件文件过大 | 复用 MAX_FILE_SIZE (10MB) 限制 |
| 多文件上传并发 | 串行上传 + 进度条 |
| 二次评估与初评分数体系不一致 | 使用相同的 prompt 模板 + 分档标准 |
